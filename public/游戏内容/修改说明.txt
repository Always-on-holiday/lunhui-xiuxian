《轮回仙途》快速修改文字

一、怎么打开
双击项目根目录里的“打开内容配置.bat”，会直接打开本文件夹。

二、怎么修改
1. 用记事本打开“界面文字.json”。
2. 只修改双引号里面的文字，不要删除字段名、冒号、逗号或括号。
3. 保存文件。
4. 关闭当前游戏的黑色窗口，再双击“一键启动互联网联机.bat”。
5. 无需重新构建，重新打开的页面会读取新文字。

如果要修改序章内容，请打开“序章规则.json”。这里可以直接调整：
- 出生五维范围、气血与灵力换算；
- 出生后可分配的命格点数，以及单项最多投入点数；
- 灵根出现权重、灵根天赋、NPC 反应和初始加成；
- 主线与支线文案、解锁条件和属性奖励；
- 童年修行选项、风险提示和属性成长；
- 出身概率、初始灵石、道具、功法、技法与隐藏天赋；
- 木傀战斗目标值、随机波动、受伤范围和结算文字；
- 死亡回退规则说明与多人遗迹预告。
- 寿元、境界增寿、体魄增寿、自动时间流速，以及修炼和事件的耗时。

三、怎么增加剧情段落
在 storyParagraphs 的方括号中添加一行文字。每一行之间必须有英文逗号，例如：

"storyParagraphs": [
  "第一段。",
  "第二段。",
  "新增加的第三段。"
]

四、注意事项
- JSON 使用英文半角双引号和逗号。
- 最后一项后面不要加逗号。
- 如果格式写错，网页会继续使用上一次构建时的默认文字，不会破坏世界存档。
- “界面文字.json”只负责文字，不会修改玩家、房间或世界存档。
- world 中的 reincarnate、resetAll、pastLives 字段控制转世确认框与轮回册提示文字。
- “序章规则.json”中的 rootRoll 使用 weight 表示相对概率。数值不必刚好加到 100，数字越大越容易抽到。
- 灵根名称中的 {elements} 是元素占位符，游戏会自动换成“金·木·水”等实际结果。
- 灵根成长评价仍保留在配置中供策划使用，但不会直接展示给玩家；灵根天赋与说明照常显示。
- 出身会按 origins 中的 weight 进行 1—总权重 Roll，并把本次点数显示在出身卡片上。
- 新生流程按“出身 → 测灵 → 命格”逐页推进；确认命格前不会显示主线、修行、行囊或战斗区域。
- 支线在条件未满足时完全隐藏，达到条件后才显示名称、说明和触发按钮。
- 完成入世后，右侧“此世命格”会常驻显示灵根与天赋，避免游玩途中遗忘。
- 死亡、残魂行动、多人复活、全员团灭轮回、三项继承和二周目特殊剧情统一配置在“轮回规则.json”；详细字段见“轮回内容编写说明.txt”。
- 支线 unlock 为 null 时会直接解锁；填写 stat 和 minimum 时，会检查指定五维是否达到要求。
- origins 控制出身。修真世家的 startingCultivationRoll 会按 weight 再抽取一部功法。
- cultivationArts、techniques 和 items 是内容目录；出身中填写对应 id，人物才会实际拥有它。
- 道具 effects 中的 contextId 决定生效场景。木傀试炼使用 wooden_trial；场景不匹配时会提示无用，不加入计算也不消耗。
- 玩家可以同时备好任意数量的有效道具。consumable 为 true 的道具只在实际生效后扣除一个，false 则永久保留。
- bonusWins 或 forceOutcome 可制作特定地点的奇效；specialResult 可先记录未来事件效果。
- hiddenTalentId 会写入角色存档但不会直接显示，等满足 revealCondition 后再由事件揭示。
- 战斗在玩家点击开战时即时计算；JSON 负责可调整参数和文案，程序负责公式、比较与结算。
- worldRules 保留世界规则和遗迹入口预告；真正的单人残魂、多人复活和全员轮回由“轮回规则.json”控制并已经启用。
- “试演身死”用于当前试玩版主动验证死亡流程；正式致死事件也会自动进入同一套残魂流程。“完全重开”只清除当前浏览器中的人物和前世记录，不会删除联机房间。
- 新规则主要作用于新出生的人物。已经开始的角色会保留出生时的气血和灵力规则，避免中途变数值。
- timeSystem.daysPerYear 控制一年按多少天计算；界面会显示约数年限，并在括号中精确显示天数。
- timeSystem.realSecondsPerDay 控制页面打开时的自动流速，默认现实 60 秒流逝游戏内 1 天；关闭页面期间不扣寿元。
- timeSystem.lifespan 控制基础寿命、体魄（当前使用 defense）、等级和境界带来的增寿。
- timeSystem.lifespan.revivalGraceDays 控制寿尽后被复活时返还的寿命天数，避免复活后立刻再次寿尽。
- timeSystem.costs 控制入世推进、支线、童年修炼、木傀试炼和随机事件分别消耗多少天。
- 寿元耗尽后当前人物不能继续行动，只能保存此世并转生；世界和其他玩家不会停止。
- 提交到 GitHub 后，其他组员也能同步这些文字修改。

随机事件内容已放在“随机事件”文件夹。先看“事件编写说明.txt”，再修改“01-新手村.json”；建议每次只改一个小部分，保存后重启试玩确认。事件引擎已经接入网页，修改后重启游戏即可生效。

第一章支线内容放在“支线”文件夹。“01-青石村.json”包含五种灵根入口、公共暗线、人物、结局和道具联动；目前是可校验的内容蓝图，下一步接入支线界面与结算引擎。

人物、物品、地点的通用操作与自由度规则放在“自由行动”文件夹。先阅读“编写说明.txt”，再复制“内容对象示例.json”增加内容。通用成功率算法已经完成，尚待具体人物与场景在试玩页面中调用。

提交内容前可以运行 pnpm content:check 检查 JSON 和引用，再运行 pnpm actions:simulate 检查概率曲线。
